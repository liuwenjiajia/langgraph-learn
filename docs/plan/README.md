## 3. 每天怎么打卡

打开当月文件，找到今天那一天。每一天长这样：

```markdown
- [ ] **2026-11-02 周一 · D3/124 · M1｜结构化输出（上）：schema 与解析**
  - [ ] ★ 30′ …
  - [ ] ★ 60′ …
  - [ ] ☆ 20′ …
  - 🎯 **完成标准**：…
```

1. **★ 是必做，合计正好 120 分钟；☆ 是有余力再做，永远不影响当天算不算完成。**
2. 子项做完就勾；**★ 全部做完，才勾当天那一行**。
3. **🎯 完成标准是证据**：一次 commit、一段输出、一个数字。拿不出证据就不勾。
4. 每天结束提交一次：`git commit -am "checkin: D3"`。周五复盘那天提交 `checkin: W2 review`。提交历史就是你的出勤记录。
5. 状态很差的日子，**最小可行的一天**：只做当天第一个 ★（≤30 分钟）并提交，其余记欠账。保持连续比做满更重要。
6. 每周最后一个工作日有一个 20 分钟的「周复盘」★：填该周末尾的五行小结（完成天数、欠账、一个数字、一个坑、一个问题）。
7. **周末**：先补欠账（周六、周日各最多 2 小时）；补完了再做该周末尾的「拓展思考」题，拓展思考不打卡。

查看进度（只读，不改文件）：

```bash
python3 scripts/checkin.py                     # 今天的任务、累计进度、欠账日
python3 scripts/checkin.py --date 2026-11-02   # 预览某一天
```

## 4. 落后了怎么办

**欠账 = 未完成的 ★ 分钟数。** 每周日晚结算一次，用脚本看「欠 ★ 共 x h」。

| 欠账 | 动作 |
|---|---|
| 0 – 3h | 下周按计划走；欠账写进周复盘，下个周末继续补 |
| 3 – 6h | 之后所有 ☆ 全部不做；下个周末必须清到 3h 以下 |
| 6 – 10h | 启用下面的「削减阶梯」，从第 1 级开始，够了就停 |
| > 10h，或连续 3 个工作日零打卡 | **停止硬追。** 整体顺延，不压缩；回来找我重排日程 |

**铁律：不一次性补多天，不让周一替周日还债。** 周日晚没补完的就带着欠账走，进上面的表。

**削减阶梯**（每一级都会降低一项验收标准，用了就在验收日写明「已降级」，不能悄悄略过）：

| 级 | 可砍的内容 | 约省 | 验收影响 |
|---|---|---|---|
| 1 | 所有 ☆ | — | 无 |
| 2 | M2 的 LlamaIndex 实现（D30–D31），改为只读文档做对照 | 3–4h | P2「双版本对照」降级 |
| 3 | M4 的 Swarm 完整实现（D71–D73），改为一个 handoff 小 demo | 4–5h | P4「Supervisor vs Swarm 对比表」降级 |
| 4 | M6 的 CrewAI / AutoGPT 实验（D118），改为读文档写取舍 | 约 2h | 六框架笔记以文档阅读为主 |
| 5 | M5 评测集从 150 条降到 100 条（D86 起） | 约 4h | 评测集「≥150」降级 |

**不能砍**：手写 tool loop；Milvus + ES 双实现与混合检索 + Rerank + Ragas；LangGraph 持久化与 interrupt；3 个 MCP Server；Judge 校准；CI 回归；P6 一键部署。这些是简历上的数字来源。
